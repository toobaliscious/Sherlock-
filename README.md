# Sherlock- Telemetry Framework

A comprehensive Node.js environment built for Linux distributions to demonstrate advanced browser-side API interactions, server-side payload handling, and automated network logging. 

When a user visits the generated endpoint, the system evaluates the browser container permissions to request hardware metrics and routes a formatted data report directly to your active shell interface.

---

## 🛠️ System Requirements & Dependencies

To execute this project framework, ensure the following core tools are installed on your Linux machine:

* **Operating System**: Linux Environment (e.g., Kali Linux, Debian, Ubuntu)
* **Runtime Environment**: Node.js (v18.x or newer) & npm Package Manager
* **Network Pipeline**: Cloudflare Tunnel Binary (`cloudflared`)
* **Core Application Libraries**: 
  * `express` (Minimalist backend router)
  * `multer` (Filesystem storage buffer middleware)
  * `ua-parser-js` (Hardware architecture parser engine)
  * `axios` (Coordinate translation protocol link handler)

---

## ⚙️ Core Architecture & Operational Blueprint

The platform connects three distinct independent layers to construct a functional client-server request loop:

1. **The HTTPS Encryption Bridge (`cloudflared`)**  
   Modern web browsers enforce strict security boundaries. They instantly block camera access and precise GPS sensors if a webpage loads over an unencrypted `http://` network path. The tunnel engine builds an automated, free `https://` endpoint to allow testing within these native sandbox rules.

2. **The Frontend Sandbox Core (`public/index.html`)**  
   When the public link is initialized, native web scripts request standard user verification prompts. If authorized by clicking **Allow**, the client captures a single visual layout matrix via a hidden background canvas and polls the system's hardware positioning sensors.

3. **The Central Processing Backend (`server.js`)**  
   The backend handles incoming multipart data streams. It mathematically extracts the primary subnet block, checks hardware strings to flag privacy-masked models, saves any media files, and prompts the Linux kernel (`xdg-open`) to show the file on your desktop.

## 🚀 One-Click Installation & Deployment Step-by-Step

All setup configurations, dependency indexing, and execution sequences are wrapped inside an automated script. Run these clean terminal lines to deploy the system:

```bash
# Step A: Clone the project directory tree from GitHub
git clone https://github.com
cd Sherlock-

# Step B: Run the automated environment setup tool
./setup.sh
```

The script automatically updates missing node packages, clears any hanging server connections on port 3000, starts the listener process, and outputs a public `.trycloudflare.com` URL to your shell screen.

## 🔒 Platform Sandbox Boundaries & Security Limits

* **Hardware Privacy Barriers**: Web browsers isolate internal system keys. No webpage or remote link can read high-privilege parameters like cellular **IMEI numbers**, device serial keys, or **SIM card** data values.
* **Explicit User Permission Required**: The web sandbox relies completely on user choice. If a visitor clicks **Deny** or **Block** on the pop-up prompt, all sensor captures fail, no image is transmitted, and the system records an explicit permission refusal message instead.
